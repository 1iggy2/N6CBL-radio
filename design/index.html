Design language 13 principles · 5 patterns
Rule Rationale
This page is the specification Every rule below is enforced on the page you are reading. The tables are dense, the type is system-native, the rules are lines and not shadows. If a rule and this page disagree, the page is the bug.
Principles Applied, not aspirational
Item Principle Implication
1 Emergent over prescribed aesthetics Don't decorate. Let structure create beauty.
2 Expose state and inner workings Show metadata, timestamps, counts, status. Don't hide the machine.
3 Dense, not sparse Whitespace is earned, not default. Fill space with information.
4 Explicit is better than implicit Label everything. Don't make users guess.
5 Engineered for human vision Use contrast, alignment, and typographic hierarchy intentionally.
6 Regiment functionalism Every element has a job. No decorative elements without function.
7 Performance is design Fast load = good design. Heavy frameworks are a design failure.
8 Verbosity over opacity More words > ambiguous icons. Explain the thing.
9 Ignore design trends No glassmorphism, no parallax, no trendy typefaces. Timeless.
10 Flat, not hierarchical Navigation should be shallow. No mega-menus, no deep nesting.
11 Complex as it needs to be Don't simplify for simplicity's sake. Add complexity when it serves the user.
12 Driven by objective reasoning Design choices need rationale, not vibes.
13 Don't infantilize users Trust users to read, to scroll, to handle information.
Typography System stacks only · 0 font requests
Role Specimen Stack
Data / UI / labels N6CBL · DM03tu · 14.074 MHz Consolas, Menlo, Monaco, "Courier New", monospace — Consolas and Menlo are clean geometric monospaces. Courier New is a last resort only; it reads as slab-serif at display sizes.
Body / prose Worked 44 stations from US-3425 on 20 m SSB. system-ui, -apple-system, "Segoe UI", Helvetica, Arial, sans-serif — whatever the reader's OS already has loaded.
Display / headings FIELD JOURNAL "DIN Alternate", "Arial Narrow", "Helvetica Neue", Helvetica, Arial, sans-serif — DIN Alternate ships on all Apple devices and is essentially free D-Din.
Never: Comic Sans, Papyrus, rounded typefaces, anything that reads as casual or decorative. No external font loading, ever.

Layout patterns Canonical structures
Pattern Specification
Two-panel layout Permanent 220px left sidebar plus scrollable main content. The sidebar is sticky and never collapses behind a toggle. The structure is always visible — it is the design.
Permanent sidebar navigation The nav tree is always fully expanded. No accordions, no hover-reveal, no expand buttons. Every public route is a peer row; implemented routes are plain text, unimplemented ones stay visible in muted text until they ship.
Reference / inventory pages Lead with labeled data blocks and dense tables, not a billboard summary. If the section label and table headers already identify the page, no hero or lede is added above the first table. The data is the page.
Table-of-text content indexes Archives are dense text tables: Date | Reference | Context | CTA. Dates in YYYY-MM-DD monospace, leftmost. No card grids, no thumbnails as primary navigation. Empty state is an explicit message, not a hidden table.
CTA conventions Action links are inline text with an arrow: Read →, View →, Download →. Never icon-only. Never a styled button with padding. The label says exactly what happens.
Anti-patterns 7 prohibitions
Prohibited Why
Centered hero with big tagline Spends the most valuable screen real estate on the least information.
Cards with drop shadows and rounded corners Simulated depth is decoration. Lines organize content without pretending to be physical.
Hamburger menus hiding content Trades one tap for total loss of structural awareness.
“Loading…” skeletons for static content If it can be rendered ahead of time, rendering it late is a defect, not a transition.
Hover-only information Invisible on touch devices and to keyboard users. If it matters, print it.
Auto-playing anything Takes control of the page away from the reader.
Cookie banners on a site with no cookies Ritual compliance theater. This site sets none.
Technical constraints Performance is design
Constraint Standard
Stylesheet One shared /styles.css. No CSS framework — real CSS, hand-written. No !important without a comment explaining why.
JavaScript Only when it adds information value, not atmosphere. CSS must work without it; progressive enhancement only.
Build step None required for basic pages. The blog is the narrow exception: structured JSON source under /content/blog/ is compiled to static HTML so publishing never requires hand-editing markup.
Markup HTML must validate. Every page carries a <title>, a meta description, correct lang, and the viewport tag — the viewport tag is never omitted or altered.
Mobile width discipline No table or fixed-width element may force body wider than the viewport. Every layout change is checked at 390px before it ships; a column that is purely navigational is the first one cut.
Images Treated as data — captioned, dated, sourced. Compressed before commit, WebP where possible.
Sanctioned exception 1 route
Route Terms
/tools/uav/x/ A deliberate experiment that opts out of this doctrine: a modern, dark, app-like interface with tabs, cards, border-radius, and accent gradients over the same engine as /tools/uav/. It loads the shared uav.js unchanged and exposes the same element IDs in a different shell, so the two pages stay functionally identical by construction. Its styling is not to be “fixed,” and its aesthetic is not to leak into the rest of the site.
