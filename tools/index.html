/tools/ — workbench index 2 workbenches / static / client-side
Tools dossier
Purpose Browser-based engineering workbenches. Each workbench groups related utilities behind a single route so the site navigator stays flat while the tool inventory grows.
Delivery Static HTML/CSS with vanilla JS. No build step. No telemetry. No external scripts. No cookies. No accounts.
Trust boundary Every tool runs in your browser. File parsers and design-file loaders never upload anything. Reference data is committed in this repo.
Scope rule A workbench earns a slot when it answers recurring engineering questions faster than a calculator app or a search engine, and stays useful offline.

Design rules commitments
Rule Reason Effect
No external scripts A field tool must keep working on a tethered phone with a flaky cell signal. An engineering tool must not phone home. Every dependency ships from this origin.
No uploads Logs and design files are the operator's data. A static page has nothing to upload to. All file parsing runs in the browser.
Show the math A calculator that only prints an answer cannot be checked. Formulas, assumptions, and reference tables let the user verify every result. Each tool exposes inputs, formulas, and models.
One route per workbench The site navigator lists every public route. Grouping utilities behind a workbench route keeps that list readable as the inventory grows. Sub-tools index from their workbench page.
